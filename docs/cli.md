# Команды

Единая точка входа — `idefy`. Все команды принимают `--json` для машинного
вывода и `-q`, чтобы не печатать сообщение об успехе.

```
idefy init [PATH]                    создать model.yaml из шаблона
idefy validate MODEL                 проверить нотацию
idefy preview MODEL [-o DIR]         нарисовать диаграммы
idefy build MODEL [-o FILE.rsf]      собрать файл Ramus
idefy open FILE.rsf                  открыть файл в Ramus
idefy schema [-o FILE]               выгрузить JSON Schema языка
idefy doctor                         проверить шаблон .rsf и путь к Ramus
```

## `init`

```bash
idefy init            # создаст ./model.yaml
idefy init модели/    # создаст модели/model.yaml
idefy init план.yaml
```

Существующий файл не перезаписывается — это ошибка использования.

## `validate`

Печатает диагностики и возвращает 1, если среди них есть ошибки. Предупреждения
печатаются, но код возврата не меняют.

```bash
idefy validate model.yaml
idefy validate model.yaml --json
```

Коды диагностик — в [справочнике по языку](dsl.md#диагностики).

## `preview`

```bash
idefy preview model.yaml                     # preview/A-0.svg, preview/A0.svg, …
idefy preview model.yaml -o картинки
idefy preview model.yaml --page A0
idefy preview model.yaml --format png
idefy preview model.yaml --dump-ir ir.json
```

Без `--page` рисуются все диаграммы, каждая отдельным файлом. Имя файла — id
диаграммы: `A-0` для контекстной, дальше id функции, которую диаграмма
декомпозирует.

При ошибках валидации `preview` всё равно рисует то, что удалось разложить:
неразрешённые стрелки просто не попадают на картинку, диагностики печатаются,
код возврата 1. Иначе `E006` пришлось бы чинить вслепую.

PNG собирается через `cairosvg`. Если его нет, команда честно об этом скажет и
предложит SVG, а не упадёт молча.

`--dump-ir` выгружает промежуточное представление — то, что видят рендеры.
Нужно для отладки раскладки.

## `build`

```bash
idefy build model.yaml               # рядом с моделью, model.rsf
idefy build model.yaml -o проект.rsf
```

При ошибках валидации не собирает ничего. От окружения не зависит: Ramus не
запускает и в системе ничего не ищет.

Геометрия в `.rsf` та же, что в превью: раскладка считается один раз.

## `open`

```bash
idefy open model.rsf
idefy open model.rsf --ramus /Applications/Ramus.app
```

Запускает Ramus с файлом. Если Ramus не найден, возвращает 3 и показывает, как
указать путь.

## `schema`

```bash
idefy schema                          # в стандартный вывод
idefy schema -o idefy.schema.json
```

## `doctor`

Проверяет шаблон `.rsf`, файл конфигурации, путь к Ramus и наличие `cairosvg`.
Отсутствие Ramus и `cairosvg` — предупреждения: сборка `.rsf` от них не зависит.
Непригодный шаблон — отказ с кодом 3.

## Машинный вывод

`--json` даёт один и тот же конверт у всех команд, чтобы агенту не нужно было
помнить, какая команда что возвращает:

```json
{
    "ok": false,
    "diagnostics": [
        {
            "code": "E006",
            "level": "error",
            "where": "A2.input[0]",
            "message": "Стрелка «проверенная заявка» не разрешена на диаграмме A0",
            "hint": "похожее имя есть у A1.output: «Проверенная заявка»"
        }
    ],
    "result": null
}
```

В `result` лежит своё содержимое на команду: список путей у `preview`, путь к
файлу у `build`, `init` и `schema`, список проверок у `doctor`. При ошибке
использования вместо `result` приходит поле `error` с текстом.

## Коды возврата

| Код | Значение                                                           |
|-----|--------------------------------------------------------------------|
| 0   | Успех, предупреждения на код не влияют                             |
| 1   | Ошибки валидации                                                   |
| 2   | Ошибка использования: файл не найден, битый YAML, неизвестный флаг |
| 3   | Проблема окружения: Ramus не найден, шаблон `.rsf` непригоден      |

## Конфигурация

Путь к Ramus нужен только команде `open`. Источники в порядке убывания
приоритета:

1. флаг `--ramus`;
2. переменная окружения `IDEFY_RAMUS_PATH`;
3. поле `ramus` в файле конфигурации;
4. автопоиск в стандартных местах установки.

```toml
# ~/.config/idefy/config.toml
ramus = "/Applications/Ramus.app"
```

Расположение файла подчиняется `XDG_CONFIG_HOME`, а переменная `IDEFY_CONFIG`
задаёт его напрямую. `idefy doctor` показывает, какой источник сработал.
