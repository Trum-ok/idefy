# IDEF0-модели через idefy

Модель пишется в YAML, всё остальное считает `idefy`: раскладку, стрелки,
картинку и нативный файл Ramus. Координаты руками не считаются, `.rsf` руками
не редактируется.

## Воркфлоу

1. `idefy init model.yaml` — заготовка. Или пишите YAML с нуля.
2. Опишите функции и их ICOM-списки.
3. `idefy validate model.yaml --json` — разберите диагностики, почините модель.
4. `idefy preview model.yaml` — получите `preview/A-0.svg`, `preview/A0.svg`, …
5. **Посмотрите картинки.** Этот шаг обязателен: валидатор не видит, что
   стрелки наложились друг на друга или что подпись уехала на блок.
6. Почините замечания, вернитесь к шагу 3.
7. `idefy build model.yaml` — соберите `.rsf`. При ошибках валидации не соберётся.

`preview` рисует даже при ошибках: неразрешённые стрелки просто не попадают на
картинку. Пользуйтесь этим, чтобы чинить `E006` глядя на диаграмму, а не вслепую.

Все команды принимают `--json` (машинный вывод в конверте `ok` / `diagnostics` /
`result`) и `-q`. Коды возврата: `0` успех, `1` ошибки валидации, `2` ошибка
использования, `3` проблема окружения.

## Правила IDEF0, которые проверяет валидатор

- Имя функции — глагол в неопределённой форме: «Обработать заявку», не
  «Обработка заявки».
- У каждой функции обязательны выход и управление. Вход и механизм — нет.
- На одной диаграмме 3–6 блоков, жёсткий предел 8. Больше — заводите уровень.
- Нумерация иерархическая и самоописывающая: `A0` → `A1`, `A2`, `A3`;
  `A1` → `A11`, `A12`. Поля `parent` нет, родитель выводится из id.
- Контекстная функция ровно одна и называется `A0`.
- Декомпозируйте 2–3 уровня, а не всё подряд.

## Синтаксис

```yaml
version: 1

model:
  name: "Обработка заявки на кредит"
  author: "Аркадий Артамонов"
  purpose: "Описать порядок обработки заявки для последующей автоматизации"
  viewpoint: "Кредитный аналитик"

activities:
  - id: A0
    name: "Обработать заявку"
    input: [ "Заявка клиента" ]
    control: [ "Кредитная политика", "ФЗ-353" ]
    output: [ "Решение по заявке" ]
    mechanism: [ "Кредитный аналитик", "АБС" ]

  - id: A1
    name: "Проверить полноту документов"
    input: [ "Заявка клиента" ]
    control: [ "Кредитная политика" ]
    output: [ "Проверенная заявка", "Список недостающих документов" ]
    mechanism: [ "Кредитный аналитик" ]

# Необязательный блок: там, где авторазрешения не хватило
arrows:
  - name: "Список недостающих документов"   # имя, как в ICOM-списках
    from: A1                                # id функции или external
    to: external                            # id функции или external
    role: input                             # необязательно: роль на приёмнике
    tunnel: dest                            # none | source | dest | both
```

Никаких других полей у функции нет. Машиночитаемая схема — `idefy schema`,
полный справочник — <https://trum-ok.github.io/idefy/dsl/>.

## Как выводятся стрелки

Стрелки не объявляются — они выводятся сопоставлением имён внутри одного уровня
декомпозиции. Сопоставление строгое: точное совпадение строки, регистр важен.

| Ситуация                                                             | Результат                        |
|----------------------------------------------------------------------|----------------------------------|
| Имя в `output` соседа и во входном списке другого                     | внутренняя стрелка               |
| Имя совпадает с ICOM родителя в той же роли                           | граничная стрелка от рамки       |
| Имя выхода никем не потреблено и его нет у родителя                   | `E006`, лечится `to: external`   |
| Один выход потребляют несколько блоков                                | ветвление, это нормально         |
| Одно имя в `output` у нескольких блоков                               | слияние, это нормально           |
| Стрелка идёт к блоку с меньшим номером                                | обратная связь                   |

## Диагностики

| Код  | Ошибка                                                          |
|------|-----------------------------------------------------------------|
| E001 | Дублирующийся `id`                                              |
| E002 | Нет родителя для `id` (например, `A21` без `A2`)                |
| E003 | У функции нет ни одного выхода                                  |
| E004 | У функции нет ни одного управления                              |
| E005 | В декомпозиции больше 8 блоков                                  |
| E006 | Стрелка не разрешена: имени нет ни у соседей, ни у родителя      |
| E007 | ICOM родителя не подхвачен ребёнком и не помечен туннелем        |
| E008 | Имя стоит и в `output`, и во входном списке одной функции        |
| E009 | Отсутствует контекстная функция `A0`                            |
| E010 | В модели больше одной контекстной диаграммы                     |

| Код  | Предупреждение                                              |
|------|-------------------------------------------------------------|
| W001 | В декомпозиции меньше 3 или больше 6 блоков                 |
| W002 | Не заполнены `purpose` или `viewpoint`                      |
| W003 | Имя функции не начинается с глагола в неопределённой форме   |
| W004 | Функция не декомпозирована, хотя у неё больше 5 стрелок      |
| W005 | Обратная связь пересекает больше двух блоков                |
| W006 | Одно имя потребляется разными блоками в разных ролях        |

## Типовые ошибки

- **Разное написание одной стрелки в разных блоках.** «Проверенная заявка» у
  одного и «проверенная заявка» у другого — это `E006`, а не одна стрелка.
  Заведите список имён потоков и держитесь его.
- **Функция без управления.** Управление — это правило, регламент или условие,
  по которому функция выполняется, а не ещё один вход.
- **Декомпозиция всего подряд.** Два-три уровня описывают процесс; пять уровней
  никто не читает.
- **Выход, который никуда не идёт.** Либо его потребляет соседний блок, либо он
  есть у родителя в `output`, либо объявите `to: external`.
- **ICOM родителя, забытый в декомпозиции.** `E007`: либо подхватите имя в
  нужном блоке, либо пометьте стрелку туннелем на диаграмме родителя.

## Чего не делать

- Не редактировать `.rsf`: это zip с дампом таблиц, ручная правка ломает его молча.
- Не считать координаты руками и не задавать их в YAML — раскладка автоматическая.
- Не подгонять имена «на глаз»: если валидатор ругается на имя, чините имя, а не
  обходите проверку.
- Не пропускать просмотр превью перед `build`.
